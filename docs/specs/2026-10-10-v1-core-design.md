## 1. Goal and success criteria

Ship a Chrome extension + web dashboard + backend that real users in Nepal/India (English UI) can install, sign into, and use daily, where:

1. A context is detected, confirmed (or soft-confirmed), and drift produces **at most one gentle, non-blocking nudge per grace window**, with real 5-minute grace that survives tab reloads, service-worker restarts and laptop sleep.
2. "Back" returns to the exact tab; "Resume" after a break reopens the context's tabs and shows the user's own note first.
3. **Page titles, URLs, raw events, resume targets and AI keys never leave the browser** (D-15). The server holds goals, context names/modes/states/site names, settings and daily totals only.
4. Works fully with **no AI key** (rules only); optional AI never blocks the loop.
5. Every user's data is isolated, exportable and deletable.
6. All 20 engine replay traces + invariants pass; backend isolation/export/delete tests pass.

Non-goals for v1: mobile app, WebSockets, adaptive/snooze-learned grace (D-4), velocity checks, achievements, mood, timer, meditation, AI planning (D-11), Firefox/Edge, payments.

## 2. Architecture

```
Chrome extension  ── does the work ──────────────────────────────────────────────
  engine/      pure step(state, input, now, cfg) → {state, effects}   (no chrome.*, no clock)
  shell        background.js (ES module SW): adapters → dispatch queue → persist → run effects
  ui           nudge card (closed shadow root) · notification fallback · popup · onboarding/consent page · blocked.html
  ai/          provider adapters: off | nano | local | key   (async, off the critical path)
  storage      chrome.storage.session (engine state) · .local (resume targets, rules, settings cache, AI key, tokens)
        │  REST + Bearer JWT: PUT /contexts/{id}, PUT /daily/{day}, GET /me
        ▼
Backend  ── remembers ── FastAPI + Postgres (Supabase) · verifies Supabase JWTs via JWKS
        ▲
        │  REST + Bearer JWT
Web dashboard (Expo web) ── Today · History · Settings
```

- **Authority (engine notes Q1):** the extension is authoritative for its browser profile. The server is a mirror. Two desktops = independent contexts. Amends SPEC P9, §5, §8.2, §17.
- **No build step** in the extension: ES-module service worker, `// @ts-check` + JSDoc checked by the repo's TypeScript, tests via `node --test`.

## 3. Accounts and backend

### 3.1 Auth
- Supabase Auth: **email 6-digit code** and **Google**. Custom SMTP (Resend free tier, tracking off) is a deploy prerequisite.
- **Dashboard** uses `@supabase/supabase-js` session handling.
- **Extension signs in separately** from its popup (email code typed in the popup; Google via `chrome.identity.launchWebAuthFlow`). Tokens stored in `chrome.storage.local`; refreshed by supabase-js. Never shares tokens with the dashboard (single-use refresh tokens).
- **FastAPI** verifies `Authorization: Bearer <jwt>` with PyJWT against the project JWKS (cached 10 min), checks `aud="authenticated"`, `exp`, issuer; `sub` = `user_id`. JWKS URL and issuer from env. Tests use a locally generated ES256 key + overridden JWKS — no network.
- First authenticated request upserts a `profiles` row. On first extension sign-in, if the profile still has the default tz, the extension `PATCH`es `tz` from `Intl.DateTimeFormat().resolvedOptions().timeZone`.
- **Settings source of truth = `profiles.settings`** (edited from popup or dashboard); the extension caches it and refreshes on popup open and every heartbeat-hour. Extension-only settings (AI option + key, related-site rules, sensitive additions, Beast Mode list) stay in `storage.local` (D-15).
- **`device_id`**: random UUID generated by the extension on install, stored in `storage.local`.

### 3.2 Schema (fresh, Alembic-managed; old hackathon tables and routers deleted)

| Table | Columns | Notes |
|---|---|---|
| `profiles` | `user_id uuid pk`, `tz text not null default 'Asia/Kathmandu'`, `settings jsonb not null default '{}'`, `created_at`, `updated_at` | settings: `grace_s` (120–900), `quiet_hours` `[{from,to}]` |
| `goals` | `id uuid pk`, `user_id`, `day date`, `title text ≤200`, `category text in (work,learning,personal)`, `status text in (open,done)`, `sort int`, `created_at`, `done_at` | index `(user_id, day)` |
| `contexts` | `id text pk` (extension-generated), `user_id`, `device_id text`, `title ≤120`, `mode`, `state`, `confidence in (inferred,confirmed)`, `started_at`, `ended_at null`, `last_active_at`, `sites text[]` (hostnames only, ≤50), `updated_at` | upsert by id; **no page titles** |
| `daily_totals` | `user_id`, `day date`, `device_id`, `focus_s`, `nudges`, `self_returns`, `recoveries`, `snoozes`, `breaks`, `longest_detour_s`, `updated_at` | pk `(user_id, day, device_id)`; **absolute values**, last write wins |

All queries are filtered by `user_id` from the token; no endpoint accepts a `user_id` parameter.

### 3.3 API (all under `/api`, all but health require auth)

| Method & path | Behaviour |
|---|---|
| `GET /health` | `{status:"ok"}` |
| `GET /me` | profile (tz, settings) |
| `PATCH /me` | update tz (IANA, validated) and/or settings (validated ranges) |
| `GET /me/export` | JSON of all the user's rows across the 4 tables |
| `DELETE /me` | delete all rows, then Supabase admin `deleteUser(sub)` via service-role key; 204 |
| `GET /goals?day=YYYY-MM-DD` | default day = today in profile tz |
| `POST /goals` | `{title, category?, day?}`; also accepts `{lines: "a\nb, c"}` → simple splitter (split on newlines; trims; drops empties; ≤20) |
| `PATCH /goals/{id}` · `DELETE /goals/{id}` | title/status/sort |
| `PUT /contexts/{id}` | idempotent upsert from extension; validates sizes; `sites` must be hostnames |
| `GET /contexts?day=` | contexts overlapping that local day; `?active=1` for the latest non-ended |
| `PUT /daily/{day}` | idempotent upsert of absolute totals for `(user, day, device_id)` |
| `GET /daily?from=&to=` | ≤31 days; summed across devices per day |

- CORS: dashboard origin(s) from env + `chrome-extension://<EXTENSION_ID>` (exact ID from env, not a regex).
- Rate limit: simple in-process per-user limiter (60 req/min) — `ponytail:` per-instance; fine at max-instances=1.
- `DEMO_MODE` seeding is removed with the old tables; demo data for the dashboard lives client-side behind `EXPO_PUBLIC_DEMO_MODE` (D-7).
- `backend/app/services/context_engine.py` and the AI service are **deleted**; the taxonomy moves to `extension/engine/domains.json` (D-10/D-12).

## 4. Extension

### 4.1 Permissions (from platform research)
```json
"minimum_chrome_version": "120",
"permissions": ["tabs","storage","alarms","idle","notifications","scripting","tabGroups","declarativeNetRequestWithHostAccess"],
"optional_host_permissions": ["https://*/*","http://*/*"],
"background": {"service_worker": "background.js", "type": "module"},
"web_accessible_resources": [{"resources": ["blocked.html"], "matches": ["<all_urls>"]}]
```
No static `content_scripts`, no `host_permissions`. During onboarding the user is asked (one click) to grant host access **only for the seed's yellow/red domains** so the nudge card can render there; Ollama `http://localhost:11434/*` is requested only if the user picks Local model.

### 4.2 Shell responsibilities
- `tabToInput(tab)`: incognito / `chrome://` / `isSensitiveHost` → `host:null` (blind); `sanitizeTitle`; longest-suffix host match.
- Single promise-queue `dispatch(input)`: load state → `step` → **persist** → run effects. Startup sends `heartbeat startup` (re-derives alarms). 60 s heartbeat alarm while a context exists.
- Effect executors: alarms; nudge (in-page card via `scripting.executeScript` where host access exists, else `chrome.notifications` with up to 2 buttons + click opens popup); `group_tab` / `focus_tab` / `reopen_group`; `persist_resume` / `drop_resume`; `sync` records → local accumulator → `PUT /contexts/{id}` (on context change) and `PUT /daily/{day}` (≤ every 5 min, and on day end); `propose_context` → popup badge + notification.
- Offline: accumulator persists in `storage.local`; uploads retry with backoff. Absolute totals make retries safe.

### 4.3 UI
- **Nudge card** (closed shadow root, bottom-right, ~320 px, no overlay, `role="dialog"`, Esc = dismiss, focus not stolen). L1 actions: **Back · This is… ▾ (part of {context} / a new task →) · +5 min · Break**. L2 = same card, mascot, playful copy.
- **First-time explanations:** the first L1 and first L2 ever shown include one line on why it appeared and a link to Settings (HabitLab finding).
- **Popup:** signed-out → email/Google sign-in; signed-in → current context (name, mode, state, time in context) · **New context** · **Pause** (30 min / until tomorrow / off) · **Break** · Beast Mode · Settings (grace, quiet hours, AI option, related-site rules list with delete, sensitive-site additions, sign out).
- **Welcome back:** popup + card: the user's note first, then context name, last ≤3 site names, **Resume**.
- **Onboarding/consent page** (opened on install, required before any observation): plain-language disclosure of what is observed, what leaves the browser (D-15), AI option choice, host-access grant button, links to privacy policy. Nothing is observed until the user clicks **Start**. (Chrome Web Store prominent-disclosure requirement.)
- **Copy:** template bank in `extension/copy/en.json` (SPEC §10.3 voice); banned-word list enforced on any AI output.

### 4.4 Engine — amendments to the engine notes
1. **New input** `{type:'cmd', cmd:'new_task', title?:string}`: from `active|grace|intervened_l1|escalated_l2` → end current ctx as completed (sync `session_end`), then treat `current` as a fresh landing with `propose_context` pre-filled with `title` (confirm immediately if title given). Popup "New context" sends `cmd:'end'` then lets detection propose on the current tab.
2. **AI for unknown hosts (D-14):** if an AI option is enabled, the shell asks it asynchronously `{host, sanitizedTitle, contextTitle} → {tier, related}`; result cached in `storage.local` per `host|contextId` and fed back as `{type:'tier_hint', host, tier, related}`; the engine applies it on the next landing only (never retroactively nudges). Unknown remains "trust" until a hint exists. AI is also used to suggest the context name in `propose_context`. Nothing else.
3. **Sync records** stay as specified but are **aggregated locally**; only context snapshots (with `sites` = in-context hostnames) and absolute daily totals are uploaded. Drift destinations and titles are never uploaded.
4. Engine notes Q1–Q5 recommendations adopted; Q6 superseded by amendment 1.
5. Add trace 21 (midnight rollover, §18 #14) and trace 22 (`new_task` from L1).

### 4.5 AI adapters (`extension/ai/`)
Uniform interface `classify({host,title,contextTitle})` and `nameContext({host,title,goals})`, each `Promise<result|null>` with a 6 s timeout:
- `off` → null. `nano` → `LanguageModel` (feature-detected; download only after a user click; offscreen document if unavailable in SW). `local` → OpenAI-compatible `/v1/chat/completions` at a user-set localhost URL. `key` → user's provider (OpenAI-compatible base URL + key; Anthropic and Gemini adapters).
- Output guard: strict JSON parse → else null; titles ≤60 chars; banned words → null. The key never leaves `storage.local` except in the request to the user's provider; settings show exactly what is sent.

### 4.6 Beast Mode
`declarativeNetRequest` dynamic redirect rules → `blocked.html` (calm copy, **Continue anyway** after a 10 s wait → session `allow` rule for that tab, removed by alarm after 10 min). Start/stop from popup only; duration required; never default.

## 5. Dashboard (Expo web)
Remove tabs Contexts/Progress/Support and screens that depend on deleted endpoints. New:
- **Sign in** (email code / Google via supabase-js).
- **Today:** goals for today (multi-line add box, tick, edit, delete); current context card (from `GET /contexts?active=1`, "Connect the extension" CTA if none ever synced); today's story from `GET /daily` (template sentences, no score, neutral on hard days).
- **History:** last 7 days, one story line each, tap for totals.
- **Settings:** grace, quiet hours, timezone; **Export my data** (downloads JSON); **Delete my account** (typed confirmation); sign out.
- Honest empty/offline states (existing `EmptyState`). Accessibility: labels/roles on all controls, ≥44 px targets.
- Mobile-native builds untouched beyond compiling (v1.1).

## 6. Error handling
- Engine never throws on unknown input → `log`, state unchanged. Shell catches executor errors per effect; a failed nudge render falls back to notification; failed sync stays queued.
- AI errors/timeouts → null → rules.
- Backend: 401 on bad/expired token (extension refreshes once, then shows signed-out); 422 validation; 404 for other users' ids (never 403, no existence leak).

## 7. Testing
- **Engine:** `node --test extension/engine` — 22 replay traces + invariant checks (engine notes §6) + seeded random-trace property test; `domains.json` longest-suffix tests (incl. `news.google.com`).
- **Extension shell:** unit tests for `tabToInput`, sync accumulator, AI output guard (stubbed `chrome`). Manual checklist for alarms after sleep, tab groups, nudge rendering.
- **Backend:** pytest — JWT verification (valid/expired/wrong aud/wrong key), two-user isolation on every endpoint, idempotent PUTs, export completeness, delete removes everything, tz-correct "today", goal splitter.
- **Dashboard:** `tsc --noEmit`, `expo lint`, `expo export --platform web`.

## 8. Build order (detailed plan follows in `docs/plans/`)
Parallel streams with disjoint file ownership: **A** engine (pure) · **B** backend · **C** dashboard · **D** extension shell + nudge + groups · **E** popup, onboarding, AI adapters, Beast Mode. Integration last (D wires A; E uses D's dispatch; C uses B's API).
